# Doodle 画图指南：`draw_board.diagram` 的正确用法与已知边界

这份笔记记录实际画图时踩过的坑，以及每个坑当前的真正行为。它面向使用 MCP 工具画图的 AI，也面向排查“为什么图和预期不一样”的人。

## 字段速查

| 想做的事 | 用这个字段 | 常见错写 |
|---|---|---|
| 设置节点标题 | `label` | ~~`title`~~（节点没有 `title`，会被 schema 拒绝） |
| 设置整张图的标题 | `diagram.title` | — |
| 标注作者 | `draw_board.author: "human" \| "ai"` | ~~`"assistant"`、`"me"`~~（枚举外，会被拒绝） |
| 让对象带名字 | `item.title`（普通 item） | 与 `diagram.nodes[].label` 不是同一个字段 |

`author` 是**整次调用**的顶层参数，不是每个对象的字段。自定义名字没有意义：画板只区分人和 AI，用来在 `get_board` 的 `HANDOFF` 里归属改动。

## `replace` 的语义

`diagram.replace: true` 会清空**整张激活画板**，只保留本次生成的对象。这一点已经过端到端验证：在 23 个既有对象上用 `replace: true` 生成 2 节点图，结果只剩 5 个对象（1 个框、2 个节点、1 个标题、1 条线），旧对象为零。

如果你看到“新图叠在旧图上”，几乎一定是这三种情况之一：

1. 调用时没有写 `replace: true`，默认就是**追加**。
2. 同一轮里既传了 `diagram` 又传了 `items`/`updates`/`remove_ids`/`layout`/`replace_board`——这种组合会被直接拒绝，不会执行。
3. 客户端显示的是本地场景，尚未收到 `board_updated` 广播。`get_board` 返回的 `items` 才是权威状态，用它判断真实对象数。

多轮迭代建议：要么每轮 `replace: true`，要么用 `remove_ids` 精确删除上一轮的 ID。追加模式现在会为重名 ID 自动加数字后缀（见下），不会再静默失败。

## 布局：什么时候会“排成一条超宽横条”

`mode: "flow"`（默认）按边推导列。过去 16 步会排成一条 3160 单位宽的横条，在视口里完全没法读。现在 **超过 6 列会自动折行**，奇数行反向，形成蛇形排布：16 步的宽度收敛到 1340，纵向展开。

显式写了 `column` 或 `row` 时不折行——作者已经表达了位置。

`timeline` / `compare` / `matrix` 只用你给的 `column` / `row`：

- 只写 `column: 0` 加 `row: 0..N`：整条时间线在同一列向下排列，这是竖排流程链的正确写法。
- `row` 的上限是 **47**（与 48 节点上限一致）。早先文档写着 12，17 步会被拒。
- 完全不给坐标的节点会各占一列，这是“并列对比”的默认行为。

## 连线

`diagram.edges` 里的每一条现在都会生成可见连线，包括：

- 相隔多列的 skip 边；
- 蛇形折行产生的跨行边；
- 纵向连接。

过去只有“同一行、相邻列”才画，16 步会静默丢掉 5 条，工具却仍然报成功。现在返回文本里的「m 条连接」等于你请求的数量。

连线可以引用**在数组里排在它后面**的对象。`parseBoard` 会在所有对象收集完成后统一校验引用，所以“先写线、再写两端节点”这种自然顺序不会再报 `Invalid line start item`。

## 追加时 ID 冲突

再次生成图时复用 `n1`、`diagram_frame` 这类 ID 非常常见。追加模式下，已占用的 ID 会自动加数字后缀（`n1_2`、`diagram_frame_2`），连线绑定同步改写，整次调用不会因为 `Duplicate board item ID` 失败。

`replace: true` 时不会加后缀——画板本来就要清空。

## 什么时候值得放弃 `diagram`

`diagram` 擅长：拓扑清晰的流程图、时间线、对比表、矩阵，节点在 48 以内。

手算坐标更稳的情况：

- 需要精确对齐到已有对象（比如在某人画好的框旁边补一条说明）；
- 布局本身就是要表达的内容（非规则的放射图、泳道、自由排布）；
- 需要在同一张图上混合多种模式。

手算时的最小可用组合：

```json
{ "items": [
  { "type": "rect", "id": "step1", "x": 40, "y": 120, "w": 200, "h": 80, "text": "第一步" },
  { "type": "line", "x": 140, "y": 208, "w": 0, "h": 60, "startItemId": "step1" }
] }
```

`line` 的 `(x, y)` 是起点，`(x + w, y + h)` 是终点，`w` / `h` 可以为负。

## 自查清单

画完先确认：

1. 返回文本里的「节点数 / 连接数」与你请求的一致；
2. 用 `get_board` 看 `items` 数量，而不是看本地画布缓存；
3. 多轮迭代后确认旧对象是否应当保留——不保留就 `replace: true` 或 `remove_ids`。
